# 0002. 共通デザインを Marp のテーマファイルに置き、本編の生成で画像を dist に写す

- 状態: 採用
- 日時: 2026-10-28 17:44 JST
- 関連: Issue #8 / 採用 PR #10 / [Issue レポート](../issue-reports/issue-8.md)

## 背景

Issue #8 で、Issue #5 の見本（紙色・藍・明朝の見出し・罫線・金色の強調）を共通デザインにまとめ、導入6枚に適用した。受け入れ条件は、別の原稿でも長い CSS を複製せずに同じデザインを使えること（[spec.md](../spec.md) 2.2）。
[ADR 0001](0001-原稿内のHTMLで図を描く.md) は、見た目の CSS を原稿の front matter の `style` に置くとしていた。これでは原稿ごとに CSS を写す必要がある。また、本編の HTML は画像を相対パスで参照するため、`dist/index.html` から挿絵が欠け、PDF ではローカル画像が読み込まれなかった。

## 決定

- 図は原稿内の HTML 要素で描く。`marp.config.mjs` の `html: true` を続ける（ADR 0001 から引き継ぐ）
- 共通の見た目は Marp のテーマファイル `themes/paper.css`（`/* @theme paper */`）に置き、`marp.config.mjs` の `themeSet: ['themes']` で登録する。原稿は front matter に `theme: paper` を書き、長い `style` を持たない
- ページ型（表紙・工程・3列・左右・まとめ）はテーマのクラスとして置き、使い方は [docs/design.md](../design.md) に書く
- `npm run build`・`build:pdf` は `scripts/build.mjs` で Marp を呼ぶ。`slides/assets` を `dist/assets` に複製し、PDF には `--allow-local-files` を付ける
- 依存パッケージは増やさない。Issue #5 の見本 `slides/design-codex.md` は独自の `style` のまま残す（比較の記録）

## 理由

- 二重実装の両案（PR #10・#11）が、同じくテーマファイルと `themeSet` を選んだ。相互レビューが、`style` を持たない別の最小原稿で HTML・PDF を生成できることを確かめた
- 変更前の生成では PDF の5枚目で挿絵が欠けることを相互レビューが再現し、変更後に表示されることを確かめた（Issue レポート 5・6章）
- 人間は両案を並べて表示し、PR #10 を採用した

## 選ばなかった案

- テーマを `slides/themes/paper-ink.css` に置く（PR #11）: 仕組みは同じ。原稿のフォルダとテーマを分け、ガイドの導線も更新した PR #10 を採用した
- CSS を front matter の `style` に残す（ADR 0001 のまま）: 別の原稿で同じデザインを使うたびに長い CSS を写すことになる

## 影響

- 次のスライドや別の発表は `theme: paper` とページ型のクラスで作れる。見た目を変えるときは `themes/paper.css` だけを直し、本編と見本の両方を生成して確かめる
- 原稿に置く画像は `slides/assets/` に置き、相対パスで参照する。配布するときは `dist/index.html` と `dist/assets/` を一緒に渡す
- 枠の幅が固定の要素はフォントの違いであふれやすい。手元のフォントに加えて CI の PDF（Noto）でも確かめる（ADR 0001 から引き継ぐ）
- 他の発表向けにページ型を増やすときや、テーマを別パッケージにするときは、新しい ADR で見直す
