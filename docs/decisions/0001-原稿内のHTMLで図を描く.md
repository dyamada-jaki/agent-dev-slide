# 0001. スライドの図は原稿内の HTML/CSS で描く（Marp の `html: true`）

- 状態: 採用
- 日時: 2026-10-28 12:41 JST
- 関連: Issue #1 / 採用 PR #3 / [Issue レポート](../issue-reports/issue-1.md)

## 背景

Issue #1（LT の導入）で、工程の流れ、3つの役割、人間が担う3つの判断を、LT の画面で関係が分かるように見せる必要があった。
Marp は既定では原稿内の HTML を表示しないため、図の描き方を決める必要があった。

## 決定

- `marp.config.mjs` で `html: true` を有効にし、図（矢印でつないだ箱、カード、判断の箱、まとめの表）は原稿 `slides/index.md` の中に HTML 要素として書く
- 見た目は原稿の front matter の `style` に CSS のクラスとして置き、ページごとに同じクラスを使い回す
- 依存パッケージは増やさない

## 理由

- 二重実装で、HTML/CSS の箱で描いた PR #3 と、Markdown の表・箇条書きだけで作った PR #2 を比べ、人間が PR #3 を採用した
- Marp CLI と Chrome だけで、HTML と PDF に同じ表示が出る。CI で作った PDF（Noto Sans CJK JP）でも、カード内の文字切れや重なりがないことを確かめた（Issue レポート 5章）

## 選ばなかった案

- Markdown の表と箇条書きだけで作る（PR #2）: 設定は変えずに済む。ただし、工程の流れや、人間と3つの役割の関係を画面で示す手段が限られる
- Mermaid などの図のライブラリ: 依存パッケージと描画の仕組みが増える。PDF での表示も別に確かめる必要がある

## 影響

- 後続のスライドも、既存の CSS クラス（`.row`・`.card`・`.step` など）を使って図を描ける
- 原稿の HTML は、本プロジェクトが書いたものだけにする。外部から取り込んだ HTML や埋め込みは置かない
- 枠の幅が固定の箱は、フォントの違いで文字があふれやすい。表示確認では、手元のフォントに加えて CI の PDF（Noto）でも確かめる
- 図のライブラリが必要になったら、新しい ADR で見直す
