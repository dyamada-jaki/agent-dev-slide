## 表示の確認

環境は macOS、Node.js 24.14.0、Google Chrome 156.0.8078.80、Orca CLI 1.4.240。`npm run dev` を `.env` の5282で起動した。

- Orca の専用タブで `set viewport 1280 720` を実行し、`innerWidth`・`innerHeight` が1280・720であることを実測。全12枚で横スクロール・画像の読み込み失敗なし。ArrowRightで1→12、ArrowLeftで12→11への移動をハッシュとsnapshotで確認した。マウス・キーボード操作であり、タッチや実機の結果ではない。
- Orca のスクリーンショットはタイル状に重複したため、同機能だけでは見た目を確認できなかった。`testing.md` 2章の代替手順で、Marp PNG全12枚・生成HTMLをheadless Chromeで1280×720に開いた全12枚・手元PDFをPopplerで1280×720に描いた全12枚を確認。文字切れ・重なり・日本語の欠け・画像欠けなし。
- 生成HTMLでもArrowRightの1→12とArrowLeftの12→11が成功。全ページの画像の`naturalWidth`、テキストノードの`Range.getClientRects()`とスライド領域を照合し、領域外の文字・未読み込み画像・横スクロールは0件。JavaScriptのpageerrorは0件。
- 4→5→6はイベントの説明→board #37の課題・したいこと→完成条件と2案の比較基準。4枚目の発表ノートで実例へ案内し、本文には接続の行を追加していない。
- PDFは12ページ（960×540pt、16:9）。CIのNoto版と対象コミットの結果はPR本文へ記録する。

生成HTMLの1280×720での実測値。枠は`getBoundingClientRect()`、文字は見出し・本文の`Range.getClientRects()`の外接矩形で測った。CSSの宣言値とは別に実物を測定している。
