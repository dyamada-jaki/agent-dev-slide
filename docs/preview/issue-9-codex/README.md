## エージェントの確認

- 環境: macOS、Node.js 24.14.0、npm 11.9.0、Marp CLI 4.5.1、インストール済み Google Chrome。対象 SHA と各コマンドの最終結果は PR 本文に記載する。
- HTML: 全12枚の1280×720 PNG を目視。日本語、文字切れ、重なり、画像欠けを確認。追加前の導入6枚と追加後の PNG は6枚ともバイト単位で一致した。本文・ノート・出典も無変更。
- PDF: Marp と Chrome で生成した12ページを macOS PDFKit で1280×720の PNG にし、全ページを目視。文字・画像・余白を確認した。Poppler はこの環境にないため、手元の PDF の画像化には PDFKit を使用した。
- Orca: 対象タブを維持し、`set viewport 1280 720` 後に `innerWidth=1280`、`innerHeight=720`、`scrollWidth=1280` を実測。snapshot→見出しクリック→ArrowRight で1→2枚目への移動を確認した。撮影はタイル状に重複し、連続キー操作もその後安定せず、全ページの見た目・連続送りを Orca だけでは確認できなかった。スマホ・タッチ・実機の確認は行っていない。
- 代替操作: 生成した実物の HTML を headless Chrome で1280×720で開き、実際の ArrowRight 入力で1→12枚目、ArrowLeft で12→11枚目を確認。画像はすべて読み込まれ、横スクロールなし。見た目は上記 PNG と PDF の全ページで確認した。
- 寸法: `getBoundingClientRect()` で、表示中のスライド左上からの相対値として実測。10枚目の比較画像は各500×281.25px、本文の最下端は654.25px。11枚目の最下端は658.98px。外周余白の設計上の下端664px内に収まる。CSS の宣言値だけを表示確認の根拠にはしていない。
- 初回2案は固定版から生成し、採用修正版は3480008の画像を無変更で複製した。初回 #6 の判断は藍色、初回 #7 は金色の箱、修正版 #6 は罫線と金色という差を、本文・画像・版ラベルで突き合わせた。
- 11枚目の工程とノートを #5 レポート8章、12枚目を9〜11章と照合。PO の確認と人間判断、採用・修正方針と実行承認、A〜C の反映と D の継続観測を分けている。固定版の README・workflow・finish-issue は GitHub API で公開ファイルの blob を取得し、参照した Git 履歴との一致を確認した。
- CI の Noto PDF は対象 head の実際の成果物を確認し、結果と run を PR 本文へ記載する。未取得のまま完了した場合は未確認としてレビューへ引き継ぐ。

## 改善の観測と引き継ぎ

- #5 の A: 承認された計画の要点・確認事項の決着を PR に記載する。レビュー担当が計画を探さずに済むかは、開発チームがレビュー時に確認する。
- B と #8 の F: 代替確認は所定の Marp PNG・PDF・headless Chrome を使用。プレビューの置き場所を最初からこのディレクトリに決め、操作バーの写り込みはなし。Orca のキー入力は一部動作したが、連続操作の制約は上記のとおり残る。
- C: 人物の新規制作なし。#12 で採用済みの外見と対応を再利用し、個々の製品名との対応は増やしていない。
- D: 確認手順を変更せず、今回の余白調整を再描画・再測定して確認した。軽量化の新しいルールは作っていない。
- E と #12 の待ち時間・モデル記録: 計画承認待ちの印を送り、追伸を check で確認した。通知滞留の有無とワーカーのモデル記録は、開発チームが Run の記録で確認する。
