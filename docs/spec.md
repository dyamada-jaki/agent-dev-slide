# agent-dev-slide 仕様

作るもの全体の目的・内容・範囲を定める仕様書。PO が、人間と決めたことを記録する。

## 1. これは何か

`agent-dev-template` の開発プロセスを、人に説明するための日本語スライド。
このスライド自体も同じプロセスに沿い、仕様から小さな Issue を切り出して段階的に制作する。

- 対象読者: AI を使った開発に関心がある開発者。
- 使用場面: 少し長めの LT。
- 持ち時間: 15分程度。
- 伝えたいこと: agent-dev-template の開発プロセスの全体像。

テンプレートや Orca を初めて知る読者にも、登場する役割と作業の流れがつながる説明にする。

## 2. 中身

説明対象の参照元と版は [sources.md](sources.md) に記録する。
元テンプレートが扱う主題は、Spec・Issue・Orca、3つの役割、Issue ごとの8ステップ、人間の判断、レビュー、記録とふりかえり。
LT 全体の構成は、下記の導入を起点に、Issue 1本の流れ、人間の判断と記録、始め方へつなぐ案で検討する。
全体の枚数と章ごとの時間配分は固定せず、計画と通し確認で調整する。

### 2.1 最初に作る部分: 全体像と役割

LT の導入として、表紙と、次の内容を説明できる最初のまとまりを作る。

- 何を説明するか: 人間と AI エージェントが、仕様づくりから実装・レビュー・マージ・ふりかえりまで進めるためのプロセス。
- Spec・Issue・Orca の関係: Spec は作るもの全体の仕様、Issue は今回実装する作業の目的・範囲・受け入れ条件を記すもの、Orca はエージェントの端末と worktree を扱う作業環境。
- 3つの役割: PO は仕様・Issue・受け入れ確認、開発チームは Issue の進行・比較・完了処理、開発者は自分の worktree で実装・レビューを担う。
- 人間の位置づけ: PO と議論し、計画・採用する PR・改善の採否を判断する。エージェントの3つの役割と、人間が担う判断を区別する。

初回は導入に範囲を絞る。8ステップの詳細、起動係の設定手順、個々のスキルの使い方は後続 Issue で扱う。
導入の枚数・レイアウト・口頭で補足する内容は実装計画で提案し、人間の計画承認を経て制作する。

### 2.2 個人用スライドデザインの検討

今後の発表を通じて Overstrata を知ってもらう意図を持ち、作品の雰囲気を取り入れた、個人用の共通デザインを検討する。今回の LT を試用する場にし、後の発表にも再利用できるルールとページの型を段階的に整える。

- ロゴや既存の絵を直接使うことを共通テンプレートの前提にしない。キャラクターが写る既存の絵は説明内容と合わないことが多いため、雰囲気だけを理由に置かない。
- 絵で表現する必要があるときは、説明内容に合う題材を選び、Overstrata の絵の画風を参照して描く。作品の舞台・物語をそのまま持ち込む必要はない。
- 人間はデフォルメ調のレナ・ヨナで表す。AI エージェントの役割は Issue #12 で採用した同じ画風の名前のない人物を使い、開発者は2人にする。同じ顔を人間と AI の役割の両方に使わない。人数が必要な場合もデフォルメ調でそろえ、写実的な人物画は使わない。
- 画風は、淡い水彩、にじみ、紙の余白、控えめな色数、柔らかい光などを参照して検討する。人物の形は上記のデフォルメ調とし、写実性を引き継がない。題材・キャラクター・画風を分けて指定する。
- 初回の表紙・説明・作品紹介の3枚は PDF で人間が確認済み。絵とロゴの直接利用を前提とする案を見直した。その後の導入3枚の比較では、下記のとおり PR #6 を修正の土台に選んだ。正式な共通テーマは、その後の Issue #8 で採用した。
- 本文は直接的な言葉で説明する。作品の絵を使うことを理由に、開発プロセスの用語を作中の言葉や比喩に置き換えない。
- 文字と絵のバランス、日本語の読みやすさ、Overstrata らしさを人間が確認する。配色・書体・サイズ・ページの型の詳細は、確認後に決める。
- 検討用の見本と本編を区別する。正式なテーマへの組み込みと導入6枚への適用は Issue #8 で完了した。追加の整備は後続 Issue の範囲・計画を決めて進める。
