# agent-dev-slide 仕様

作るもの全体の「何を・なぜ・どこまで」を持つ地図。PO が、人間と決めたことを記録する。

## 1. これは何か

`agent-dev-template` の開発プロセスを、人に説明するための日本語スライド。
このスライド自体も同じプロセスに沿い、仕様から小さな Issue を切り出して段階的に制作する。

- 対象読者: AI を使った開発に関心がある開発者。
- 使用場面: 少し長めの LT。
- 持ち時間: 15分程度。
- 伝えたいこと: agent-dev-template の開発プロセスの全体像。

テンプレートや Orca を初めて知る読者にも、登場する役割と作業の流れがつながる説明にする。

## 2. 中身

説明対象の参照元と版は [sources.md](sources.md) に記録する。
元テンプレートが扱う主題は、Spec・Issue・Orca、3つの席、Issue ごとの8ステップ、人間の判断、レビュー、記録とふりかえり。
LT 全体の構成は、下記の導入を起点に、Issue 1本の流れ、人間の判断と記録、始め方へつなぐ案で検討する。
全体の枚数と章ごとの時間配分は固定せず、計画と通し確認で調整する。

### 2.1 最初に作る部分: 全体像と役割

LT の導入として、表紙と、次の内容を説明できる最初のまとまりを作る。

- 何を説明するか: 人間と AI エージェントが、仕様づくりから実装・レビュー・マージ・ふりかえりまで進めるためのプロセス。
- Spec・Issue・Orca の関係: 仕様は作るもの全体の地図、Issue は今作る一片、Orca はエージェントの端末と worktree を扱う作業環境。
- 3つの席: PO は仕様・Issue・受け入れ確認、開発チームは Issue の進行・比較・完了処理、開発者は自分の worktree で実装・レビューを担う。
- 人間の位置づけ: PO と議論し、計画・採用する PR・改善の採否を判断する。人間を3つのエージェントの席のいずれかとして数えない。

初回は導入に範囲を絞る。8ステップの詳細、起動係の設定手順、個々のスキルの使い方は後続 Issue で扱う。
導入の枚数・レイアウト・口頭で補足する内容は実装計画で提案し、人間の計画承認を経て制作する。

## 3. 決まりごと

- 説明対象と本プロジェクトの運用設定を区別する。説明は参照元で裏付ける。
- 制作は [workflow.md](workflow.md) の Spec → Issue → 計画 → 実装 → レビュー → マージ → ふりかえりに従う。
- 1つの PR は1つの Issue を扱い、人間による計画承認・採用判断・改善の採否を保つ。
- 内容の正しさ、スライド表示、自動確認、人間による通し確認を分けて記録する。
- 制作環境の初期設定は Markdown／Marp、16:9、HTML・PDF 出力。原稿は `slides/index.md`、生成物は `dist/`。これはセットアップ時の暫定選択で、希望があれば本文制作前に変更する。
- 公開してはいけない資料や認証情報を含めない。

## 4. 区切り

### 区切り0: 制作環境の準備

- 達成の確認: `npm ci` 後に `npm run check` が成功し、ブラウザと PDF で日本語の初期原稿を表示できる。
- スライド向けのエージェントガイド・検証方針・CI をそろえる。
- GitHub ラベル・PO 登録・起動係を用意する。起動係の有効化は初期準備の main 反映後に行う。

### 区切り1: LT の導入で全体像と役割が伝わる

- 達成の確認: 発表者が HTML または PDF の導入を順に表示して説明し、「何をするプロセスか」「Spec・Issue・Orca の関係」「3つの席と人間の役割」を説明できることを確かめる。
- エージェントは参照元との一致、HTML・PDF の表示とページ送り、自動確認の結果を記録する。
- 人間は実際に使う画面で読みやすさと説明のしやすさを確認する。15分での全編の通し確認は本文がそろった段階で行う。

### 今はやらないこと

- 説明スライド全体の一括制作
- 枚数・デザインの計画承認前の固定
- 元テンプレートのプロセスやスキルの改変
- 公開サイトのホスティング
